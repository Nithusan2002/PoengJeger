# Produktvurdering

Les `docs/product-brief.md`, `docs/roadmap.md`, relevante beslutninger og berørt produktkode.

1. Definer brukerproblemet før den foreslåtte løsningen: bruker, mål, dagens løsning og hvorfor den ikke er nok.
2. Vurder frekvens, alvorlighet, spart tid og om kampanjeinformasjon blir lettere å forstå eller bruke.
3. Foreslå minst ett enklere alternativ, for eksempel redaksjonell prosess, veiledning, filtrering eller en mindre datamodell.
4. Vurder teknisk kompleksitet, UX, manuelt vedlikehold, innholdsbehov og juridisk eller kommersiell risiko.
5. Klassifiser forslaget som `Må ha`, `Burde ha`, `Kan vente` eller `Ikke bygg`, med begrunnelse.
6. Definer en målbar suksessindikator, som åpning av kampanjedetaljer, lagringer, varslingsaktivering eller redusert redaksjonelt arbeid.

Ikke skriv produksjonskode som del av vurderingen. Skill bekreftede krav fra antakelser og anbefalinger.

Lever: problem, målgruppe, forventet brukerverdi, antakelser, enklere alternativ, risiko og vedlikehold, MVP-klassifisering, suksessindikator, anbefaling og neste tekniske oppgave.
